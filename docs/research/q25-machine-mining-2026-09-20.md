# Q25：让机器搜索持续供给 GPU，并按误差使用混合精度

日期：2026-09-20。范围：2025 年起的论文（“2024 年后”），结合当前 Q25 实现。
论文机制、本文提出的工程方案、已实现并测量的功能分别说明；论文市场收益不等同于 Q25 可复现收益。

## 建议

**算法部分已由[后续原文调研与具体规格](q25-alpha-generation-algorithms-2026-09-20.md)取代。**
此前提出的文法生成/变异/交叉属于遗传规划（GP），C++ 仅是实现语言，不能当作算法答案。
后续建议优先验证“组合条件 GFlowNet + 共同补全的局部动作比较”，直接以成本后组合改善学习，
并把 GP、随机文法、CEM/EDA 作为公平基线。该生成器尚未实现或测得优于基线。
本文保留原始工程设计供对照；下文混合精度实现与实测记录仍有效。

GPU 忙只是必要条件。需要同时提高“每秒新的有效行为”和“单位搜索预算的样本外组合改善”，
不能通过重复参数、重复持仓或反复窥视验证集制造吞吐数字。

## 仓库中能复用什么

- `tmp/q25_funnel/` 已有 CUDA 批评估、真实组合持仓、成本后 gate、参照版本检查。
  这是新搜索器唯一评价入口，不再建一套单 alpha gate。
- `search/alphasage/gfn_trainer.py` 有批量轨迹采样，但奖励回调逐个调用旧 evaluator；
  `gfn_reward.py` 用 NumPy 处理行为描述子并更新旧 `AlphaPool`。不能直接称为 Q25 GPU 搜索。
- `search/gp/gp_baseline.py` 是 DEAP 强类型 GP，注释和实现仍面向旧单体/CV edge 奖励、CPU 评价。
  可借文法和变异的定义，不能直接接回旧 `evaluate_alpha`。
- `search/tail_diversity/dns_archive.py` 是 NumPy 原型。可借“更优近邻”的选择机制，生产数值实现须迁到 C++/CUDA。
- `fusion.py` 已将 pointwise 子图按结构编译、常数参数化。按结构组织搜索可复用 kernel，
  减少新结构反复 JIT。参考 FACT 的“可验证片段组合”，不宣称复现了论文的全部系统。

旧搜索器的领域假设（短表达式、单体门槛、IC/edge 奖励）不应默认为新组合搜索的约束。
本次没有迁移或删除这些独立研究目录，也没有宣称完整机器搜索器已经实现。

## 机器搜索设计

本节为早期 GP 工程方案，保留作基线说明；新的生成算法、奖励、相关性政策和组合重配见后续规格。

### 1. C++ 生产者

使用紧凑 AST/opcode 数组：算子 ID、输入槽、窗口、常数、输出类型、有效时域、结构哈希。
生成和变异在 C++ 完成，Python 只传递批次和记录元数据。

保留四类提案通道：随机合法结构、优秀父本的子树替换/交叉、窗口/阈值邻域搜索、档案中不同
行为的构件组合。起步等额分配，之后按“新增有效行为/计算秒”和组合改善回报调整比例；始终
保留随机探索份额。这是工程起点，不是论文推荐的固定超参。

模板例：`事件(字段,窗口) × 条件(上下文,阈值)`。一次 LLM 机制提案可以给出字段候选集、
窗口范围、阈值域、允许替换的子树；机器负责生成数千个合法邻域样本。
参数族共享 kernel，但新结构必须持续占有配额，防止只把一个旧 alpha 的参数扫得越来越细。

### 2. 有界队列和 CUDA 消费者

生产者一次生成例如 8192 个 AST；**这不是 GPU 持仓 batch size**。
队列低水位 2 个评估批次、高水位 8 个，满时停止生产。GPU 批次按空闲显存和实际吞吐调节。
目标是有效、未重复候选供给速率至少达到消费速率的 2 倍；该数值是工程目标，尚未测量生产者。

流水线：生成 → 结构去重/合法性 → 按 kernel 结构分组 → CUDA 信号与持仓 → 行为去重 →
组合权重试探 → gate → 更新研究档案。需要保持首轮 JIT 和预热吞吐分开计量。
小模型训练低频异步进行，推理用固定版本快照；训练落后时继续从 C++ 文法生成，不能停下回测等待训练。

先在 C++ 做结构去重。交换律规范化必须遵守 NaN 和浮点语义，不能任意重排结合律。
CUDA 上计算合法时域、交易掩码一致的持仓指纹；哈希命中后比较真实持仓再丢弃。
近似行为距离只影响优先级，不能因收益相关性高直接否决有成本对冲价值的构件。
同一前缀/滚动子图复用设备缓存，但用有界缓存，防止大规模 DAG 把显存耗尽。

### 3. 目标由组合决定

对组合版本 v 的持仓 P 和候选持仓 A，真实试探：

`W(w) = (1-w) P + w A`，按该持仓重新计算交易成本和净收益。

最终准入仍同时要求近期加权 Sharpe 增量至少 0.01，全期 Sharpe、CAGR、近期加权对数增长不下降。
候选单独的 Sharpe、年收益或空仓年份不能成为提前否决条件。
这里的 0.01 是工程改善幅度，不是统计显著性。

研究档案需要连续反馈，不能只存 0/1 gate：保存各权重下四个组合增量、约束违反量、
成本、行为描述子、结构复杂度和耗时；以可行性优先的 Pareto/局部竞争方式选父本。
不可行构件也可以因新行为留在研究档案，但不能进入最终组合。
若后续训练 GFlowNet，可对按参照重算后的排序分数做有界正值映射；不能直接对带符号收益增量取 log。

每个样本保存 `(data_version, split, portfolio_version, precision_contract, seed, AST, metrics)`。
一轮 GPU 批次冻结组合 P；接受一个构件后版本递增，其他候选必须对新参照重评。
收益序列/持仓可重用，旧组合奖励不能当作新参照的监督标签。这正是 AlphaQCM 指出的非平稳问题。

### 4. 不让海量搜索变成海量过拟合

按时间做训练、选择验证、最终留出；窗口/滞后标签跨界处做适当 purge，参数归一化只看过去。
当前历史池和“全期”结果已经被挖掘看过，不能重新命名为未见测试集。
若已有数据全部参与过选择，真正未见表现要从随后新增时间区间获得。

训练期进行多起点/不同种子搜索，验证预算和查看次数事先固定。最终留出仅评估冻结的组合。
扰动、滑点升高、相邻参数等稳健性检查用来选择组合和记录脆弱性，不回退成单 alpha 指标门槛。
比较方法必须同时报告固定墙钟预算和固定回测次数，包含生成、编译、训练、数据传输和评价总成本。

## 混合精度：本次已经接入生产

实现为 CUDA 模板内核，Python 只做 GPU 数组编排；没有生产 CPU 回测。
配置默认 `precision=auto`，生产协议 `combo-cuda-v4`，旧协议 checkpoint 不混用。

| 计算阶段 | 精度及原因 |
|---|---|
| 因子、比较/排名/状态信号 | 本次保留 FP64。阈值附近的舍入会改变离散持仓，这类误差不能用连续收益误差预算兜底。 |
| 大量组合试探的价格、持仓、逐日递推 | FP32 CUDA 算术；不是仅将 FP64 输入压缩为 FP32 存储。 |
| 日收益输出、均值/方差、对数收益、Sharpe/CAGR | FP64，避免跨数千天的统计累积误差。 |
| 每候选中间权重校准、超预算/异常/低方差、可能通过的完整权重网格 | GPU FP64。最终写入组合的持仓权重由 FP64 结果决定。 |

每条候选有三个误差参照：一个靠近 0.5 的真实组合权重、权重 1 的已有单候选结果、组合参照本身。
单日收益绝对误差预算默认 `1e-6`，即 0.01 个基点。若校准超限，自动 FP64。
通过 `max(预算,16×校准误差)` 扩展误差范围，推导四个 gate 指标的可能上界；仍可能通过的任何
权重点都会触发该候选全部权重的 FP64 选优。接近零波动、非有限结果、破产、越出校准持仓域也升级。
精算发现误差突破扩展范围，当前批次全部恢复 FP64，当前参照后续关闭低精度剪枝。

这套范围是经验校准加保守余量，**不是所有未校准权重点的严格区间算术证明**。
最终误收由 FP64 准入拦截；远离边界的近似拒绝仍应通过离线全 FP64 回放统计漏选率。
不能把有限样本零翻转解释为数学上永不漏选。误差预算可以收紧，过严时系统自动退回更多 FP64，
速度收益也会降低；并非按“消费卡用 FP32、服务器卡用 FP64”的型号规则硬切。

本机 T1000 是 FP32/FP64 吞吐比 32:1、4 GiB 的显卡。V100S 关闭期间未联系云端。
端到端测试包括因子执行、候选回测、整个组合网格、校准/精算、统计和主机结果序列化。
低层纯 mixed 是速度上限对照，生产 auto 的实测应单独报告。结果见下节。

## 实测记录

运行命令（本地 CUDA 依赖已由脚本配置）：

```powershell
./scripts/q25_gpu.ps1 scripts/smoke_q25_combo_gate.py
./scripts/q25_gpu.ps1 scripts/verify_q25_combo_gpu.py --precision --precision-count 256 --precision-batch 32
```

结果由 `tmp/q25_cuda/local_precision.json` 输出，固定结果保存为本目录的
`q25-precision-t1000-batch32.json`、`q25-precision-t1000-batch64.json`。
265 个输入（现有成员、从真实表达式池均匀取样、边界样例），260 个有效候选，4262 天、73 个资产。
对当前四成员组合、初始两成员组合、等权种子分别比较全部权重点，合计 780 次准入比较。
每种模式一次额外预热，随后交替顺序计时三次。计时参照是当前组合；不是未来任意池的速度保证。

| 本机批次 | 全 FP64 端到端 | 纯 mixed 对照 | 生产 auto（含校准/精算） | auto 提速 | CUDA 池保留量 |
|---|---:|---:|---:|---:|---:|
| 32 | 22.38 条/s | 77.02 条/s | 49.65 条/s | 2.22× | 1.22 GiB |
| 64 | 22.29 条/s | 81.55 条/s | 52.41 条/s | 2.35× | 2.19 GiB |

这里的池保留量是进程末尾 CuPy 分配池保留值，不是整个设备总显存峰值。
生产 auto 两个 batch 均零 gate 翻转、零最终选权变化。当前组合 5/260 条需完整 FP64 精算；
等权种子 142/260 条、初始组合 6/260 条需精算。等权种子有 130 个通过者，初始组合有 2 个，
当前组合无通过者，故测试同时包含大量通过与拒绝。

纯 mixed 的有效候选最大单日收益误差为 `2.63e-7`（约 0.00263 个基点）；
可比权重点的最大指标绝对误差为 `3.40e-5`。纯 mixed 本样本也没有 gate 翻转，但这不授权它绕过自动校准。
5 个专门持仓样例覆盖全现金、真实组合、非法非流动持仓、满额原始目标、微小敞口；
非法非流动持仓在 FP64/FP32 下都出现破产并被拒，最大误差 `1.26e-5`。

6 项生产回归全部通过，包含组合重建/过期判定、因果性、禁止 CPU 回测、Python alpha 重建、
融合算子域、精度预算及 gate 边界。将单日误差预算收紧到 `1e-14` 会触发 FP64，
将最小 Sharpe 增量放在真实候选边界两侧 `±1e-7`，auto 与 FP64 判断一致。
独立 C++ 对照的 FP64 最大日收益误差 `1.78e-15`。

这些是有限真实样本加边界测试，不是新 alpha 的样本外盈利证明；本次也没有重新挖掘或改写现有组合库。

## 实施顺序与验收

以下为早期工程路线记录；搜索算法的当前建议和对照验收以[后续规格 §11](q25-alpha-generation-algorithms-2026-09-20.md#11-如何证明值得进生产)为准。

1. **已实现：**误差驱动的生产混合精度、FP64 准入、设备内存批次上限、离线误差/决策/吞吐比较。
2. **下一阶段：**C++ 类型文法生产者、有界队列、结构/持仓去重、现有 Q25 CUDA consumer。
   先测无 LLM 的新候选供给速率、GPU 等待比例和每秒不同持仓，建立真实基线。
3. **随后：**组合条件研究档案、父本选择、版本化反馈；按冻结时间划分比较随机文法、GP/DNS。
4. **最后再加：**批量 GFlowNet/代理模型，比较其增加的学习成本是否换来了单位时间的样本外组合改善。

进度面板至少显示：生成/合法/结构重复/行为重复计数，候选/s、权重试探/s、队列长度、GPU 空等时间、
显存、校准误差、FP64 升级比例、参照版本、接受计数、训练/验证组合指标。不能只显示程序还活着。
