# L4：提交阶段复用程序评估结果

[English](README.md) · [汇总数据](summary.json) · [分段耗时](stages.csv)

当 `evaluate` 与 `commit` 之间的 `ResearchContext` 未发生变化时，直接复用评估结果可省去提交阶段的第二次账户重放。在 256 个有状态程序上，「查询＋有序提交」由 `42.301 秒` 降至 `20.851 秒`（`2.03×`），从打开到关闭的完整耗时由 `44.496 秒` 降至 `23.116 秒`（`1.92×`），收益、指标、成交统计、权重与准入结论保持一致。

上述三组压力候选均未入选，`commit` 全程组合上下文未变。若批次中有前置候选入选并修改了组合，后续候选仍需按新组合重新重放（对应耗时见[连续入选与调权报告](../program-transitions-l4-20261117/README.zh-CN.md)），因此约 `2×` 的改善仅对应上下文未变的提交场景。

实验运行在单张 NVIDIA L4（23,034 MiB，驱动 580.82.07，每条件单次运行）上：8 个合成加密现货标的、2 天 5 分钟 Bar、192 个 15 分钟决策、576 个事件、48 个小时统计点，双 FP32 算术，`Admission(weight_steps=4)`。改动前后收益数组逐位一致（521 项回归检查通过，指标误差与决策差异均为 `0`）。内存仅保留最近一批主机端报告摘要，不缓存历史批次、持仓或活动账户；[summary.json](summary.json) 中的峰值显存为 20 ms 采样下界。
