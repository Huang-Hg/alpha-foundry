# L4：现有 GFlowNet 挖掘端到端速度

[English](README.md) · [简体中文](README.zh-CN.md)

**8 轮、4096 个普通候选的完整挖掘循环耗时 5.032 秒；含会话打开和关闭为 6.186 秒。** 加上 192 个配对探针，共处理 4288 次提案；按每轮去重后累计评价 2959 次，最终有序接纳 8 条。

直接调用现有 `foundry.mine()`，未替换或删除 `search/`。GFN 32 隐藏单元神经策略、Trajectory Balance、配对教师、组合奖励、Archive、提交和 CEM 重配都使用原实现。相对 `8045a92`，代码仅增加基准入口、分发和报告；搜索与数值核未变。

**执行位置：**候选评价、回测及组合试算在 L4；现有 GFN 采样/训练和 CEM 提案仍是 C++ CPU。此次只有 GPU 类型运行时，没有独立 CPU 对照，不能据此称为全 GPU 训练。

| 阶段 | 累计耗时 | 执行位置 |
| --- | ---: | --- |
| GFN 采样 | 0.160 s | C++ CPU |
| 候选评价与奖励 | 2.943 s | CUDA + 主机编排 |
| GFN 训练 | 1.107 s | C++ CPU |
| 有序提交 | 0.151 s | CUDA + 主机 CAS |
| CEM 重配 | 0.226 s | C++ 提案 + CUDA 试算 |

训练与提交/重配重叠，阶段累计时间不可简单相加。挖掘墙钟包含诊断、Archive、状态和 checkpoint IO 等开销；打开会话另用 1.025 秒，策略初始化 0.004 秒。

## 学习和准入确实发生

每轮 512 个普通候选、2 个探针组，4 次梯度更新，共 32 次；固定种子 25，学习率 0.002，OPD 强度 0.1。8 轮的批内训练 loss 均下降；策略权重摘要排除了 RNG 状态，确认参数更新。第 2、7 轮各采纳一个可靠教师，6 轮重配改变权重；总计 43950 次准入权重试算、903 次重配评价。

| 轮次 | 训练前 loss | 训练后 loss | 可靠教师数 |
| --- | ---: | ---: | ---: |
| 1 | 423.674 | 403.335 | 0 |
| 2 | 366.980 | 349.293 | 1 |
| 3 | 368.812 | 346.984 | 0 |
| 4 | 374.096 | 352.422 | 0 |
| 5 | 347.031 | 327.904 | 0 |
| 6 | 307.461 | 290.328 | 0 |
| 7 | 296.489 | 282.195 | 1 |
| 8 | 349.206 | 329.543 | 0 |

各轮候选和奖励会改变，不能把跨轮 loss 当成固定验证集曲线。8 次接纳均核对了对应的硬准入通过记录；报告保存了逐候选决策和最终权重。

## 条件与适用范围

- NVIDIA L4 23 GB；269 行×500 美股，统计窗口 249 个交易日，成本 0.0005，双 FP32 账户/统计。GPU 采样显存峰值 5010 MiB。
- 32 MiB 紧凑缓存、256 候选驻留批次、32 个 Archive 槽位；没有增加大缓存。
- 40 项契约检查、6657 个子用例通过，39.94 秒；随后 32 候选×1 轮 smoke，再测 512 候选×8 轮一次。未进行重复种子或 CPU 对照。
- GPU/CuPy 编译缓存已由契约检查和 smoke 预热；加载、设备打开和训练均在报告中明列，原始日志保留。
- 此处含模型采样和学习，候选分布、重复率与固定 4096 公式语料不同，不能用 5.032 秒与固定语料耗时直接计算加速比。
- 这是历史窗口内的策略发现；未做监督模型的样本外 walk-forward，不代表样本外策略有效性。`judge_family` 独立稳健性审查不在默认 mine 调用中。
