# 固定 Colab CPU：候选求值与权重试算并行

[English](README.md) · [阶段耗时 CSV](flows.csv) · [汇总指标](summary.json) · [1 worker 报告](workers-1/report.zh-CN.md) · [8 worker 报告](workers-8/report.zh-CN.md)

在同一台固定配置的纯 CPU Colab 实例上，启用 8 worker 后 4,096 条公式的「评价＋有序提交」耗时由 **215.660 秒降至 106.645 秒（2.02×）**。1 worker 与 8 worker 报告数值零差异，候选顺序、准入判定与最终入选权重一致（有效 4,058 条，入选 28 条）。

## 端到端耗时

「评价」含算子求值、信号分配、账户模拟、统计归约与准入权重试算；「有序提交」含组合演进过程中的必要重评与权重试算；「合计」不含打开、加载与预热，最后一列覆盖从打开到关闭的完整耗时。

| 4096 条公式 | 评价 | 有序提交 | 评价＋提交合计 | 打开至关闭 |
| --- | ---: | ---: | ---: | ---: |
| CPU（`workers=1`） | 107.637 s | 108.023 s | 215.660 s | 215.811 s |
| CPU（`workers=8`） | 54.997 s | 51.648 s | 106.645 s | 106.783 s |
| NVIDIA A100 | 2.931 s | 3.760 s | 6.691 s | 6.934 s |
| NVIDIA L4 | 3.710 s | 4.100 s | 7.809 s | 8.098 s |

相对该固定 8 worker 并行 CPU 基线，归档的 A100 与 L4 在 4,096 条公式上的速度比分别为 **15.94×** 与 **13.66×**。在 64 条公式规模下，CPU 耗时由 `4.113 s` 降至 `2.098 s`（A100 / L4 分别为 `0.421 s` / `0.403 s`）。

## 并行配置与内存边界

- **CPU 配额：**AMD EPYC 7B12，8 vCPU（4 核 × 2 线程，亲和性 `0–7`，无 cgroup CPU 时间配额限制），两种 worker 数使用同一实例、同一编译产物与同一候选顺序。大负载下进程 CPU 时间 / 墙钟时间比值由 `0.99` 升至 **`3.50` 核**。
- **并发实现：**单进程在工作线程间共享不可变行情面板；原生算子核与账户核释放 GIL，内部 `OMP_NUM_THREADS` 与 `OPENBLAS_NUM_THREADS` 均固定为 `1`；组合演进保持单写者顺序提交。
- **内存上界：**CPU 候选批次上限为 32（GPU 为 256），均使用 32 MiB 紧凑收益/报告缓存，在途 CPU 任务不超过 8 个；不复制多进程面板、不驻留表达式中间结果、不缓存全量试算账本。临时试算账本按 `O(workers × T × S)` 扩展；周期采样记录的 `VmHWM` 为 `612.5 MiB`（1 worker）与 `636.4 MiB`（8 worker），属于观测下界而非完整峰值追踪。

## 验收与局限说明

- **并发与算子验证：**smoke 在 `9.58 s` 内通过 69 项检查（6,693 个子用例），现金账户与永续事件的串行/并行结果逐位一致；每个 worker 条件通过 158 项检查（6,660 个子用例），覆盖全部 66 个算子的 124 个窗口条件及 64/4,096 公式流程，每条件预热 1 次、测量 1 次，无重复随机种子。
- **误差范围：**1/8 worker 报告最大绝对误差为 `0`；GPU 相对 CPU 的最大尺度误差为 `7.40983567e-07`（`abs(actual - reference) / max(1, abs(reference))`），候选顺序、准入结论、拒绝原因码与选中权重无差异。
- **边界声明：**本次运行并非完整的 GPU / RPC / 私有生产基线回归，私有基线未改动也未重录。A100 与 L4 行复用 2026-11-16 在相同输入（`269 × 500` 美股、`0.0005` 成本、收盘决策次日开盘成交、CPU 原生算术对照 CUDA 固定双 FP32、无结果依赖复算）下的归档测量，仅作跨设备参照，不代表重新测量了新的 GPU 调度包装层；早期 Xeon 约 400 秒结果使用不同硬件，不作为提速分母。原始日志与源码归档保留在本地 `var/runs/`。
