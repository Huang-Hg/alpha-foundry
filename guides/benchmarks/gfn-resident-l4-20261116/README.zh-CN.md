# L4：GPU 驻留采样与轨迹复用

[English](README.md) · [简体中文](README.zh-CN.md)

**4096 个普通提案的挖掘循环从 7.889 秒降到 6.168 秒（减少 21.8%）；包含准备、打开和关闭的总时间从 8.921 秒降到 8.586 秒（减少 3.8%）。** 初始化开销没有被从总时间中删除。后七轮采样平均从 0.1744 秒降到 0.0866 秒。

前缀状态、合法动作掩码和随机抽样现在留在设备上，逐 token 循环无 CPU 回读。只有探针小批次是否成功与最终公式 token 回到主机。训练直接使用采样时记录的轨迹；SGD 优化器只初始化一次，每次训练显式设置调用方的学习率。

优化器首次准备被移到初始化阶段。因此应同时看准备与训练：两者合计 2.215 → 2.162 秒，不能把训练调用中减少的全部耗时当成计算加速。阶段会重叠，不能简单相加替代端到端墙钟。

同一 L4 型号、269 行×500 美股、研究快照、参数和初始网络权重；旧结果复用上一轮保存的证据。设备 RNG 改变了公式序列，本次共 4288 次提案（192 个探针）、2968 次轮内唯一评价、8 次硬准入接纳。这是流程对比，不是完全相同公式序列的核测速，也不宣称两轮入选策略相同。

## 正确性与资源

- Smoke 后执行针对性检查：47 项及 6785 个子用例通过，用时 96.76 秒；随后只测一次 8×512 流程，无额外种子重复或 CPU 对照。
- 合法动作掩码与主机规则对照零差异；前缀特征最大绝对误差 6.42e-8。TB 梯度误差 1.11e-6，含教师缩放和裁剪的单步参数误差 1.19e-7。
- 保留三兄弟动作、共同支撑分布、四个不同共享后缀、40 次后缀尝试上限、24×请求数的前缀尝试预算，以及教师投票/KL/置信门控。奖励、Archive、硬准入、账户与算子源码不变。
- 检查了优化器复用、旧批次轨迹释放和检查点精确续跑。新协议 `foundry-gfn-torch-v2` 保存设备随机状态，拒绝旧协议和不同设备类别。
- 轨迹存储为当前批次的 `O(B×L×(F+A))`；探针临时空间最多四个前缀×40 次后缀×三分支，按块释放。研究测量缓存仍为 32 MiB，没有历史回放缓存。
- PyTorch 张量分配峰值 30.08 → 36.17 MiB；全设备采样峰值 4340 → 5774 MiB。总峰值增长尚未逐分配归因，报告保留这一限制，不声称整体显存下降。
- 首次 smoke 含编译与准备；正式用例使用已有磁盘编译缓存，但在独立进程执行。GPU 已释放，未重录 production 基线。

历史原生 C++ 学习器流程曾测得 5.032 秒循环和 6.186 秒总时间；本版仍未超过该历史结果。不同随机候选工作量限制了这种跨实现比较。
