# CUDA 滚动算子优化

[English](README.md) · [完整对比 CSV](comparison.csv) · [优化前报告](baseline/report.zh-CN.md) · [优化后报告](optimized/report.zh-CN.md)

在同一台 Colab RTX PRO 6000 与美股面板（`269 日 × 500 资产`）上，对比分块滚动核优化前后全部 66 个算子、124 个窗口条件的耗时与精度。4,096 条公式的「评价＋有序提交」耗时由 **2.8047 秒降至 2.7699 秒**。

| 算子（窗口 20） | CPU（微秒） | CUDA 优化前（微秒） | CUDA 优化后（微秒） | CUDA 提速 |
| --- | ---: | ---: | ---: | ---: |
| `ts_std` | 240.05 | 437.27 | 233.44 | 1.87× |
| `ts_slope` | 132.51 | 325.81 | 236.41 | 1.38× |
| `ts_av_diff` | 87.60 | 195.70 | 121.42 | 1.61× |
| `ts_backfill` | 33.13 | 76.33 | 22.51 | 3.39× |

| `ts_corr` | 1101.91 | 872.47 | 421.53 | 2.07× |
| `ts_cov` | 701.61 | 448.81 | 318.29 | 1.41× |

窗口 `2 / 20 / 120` 的全部逐项数据见 [comparison.csv](comparison.csv)。在单张 `(269, 500)` 小面板单算子独立调用下，受内核启动开销影响，简单逐元素算子（`abs`、`add_const`、`div`、`gt`、`inv`、`is_nan`、`left_tail`、`mul_const`、`neg`、`not`、`not_equal`、`right_tail`、`sign`、`square`、`sub`）及少数短序列滚动算子单次调用耗时仍高于 CPU（多候选批量求值时由多流并发摊薄）。

## 数值一致性与实现要点

- **输出完全一致：**优化前后 CUDA 在 `1 / 64 / 4096` 条公式上的准入决策、选中权重与最终组合零差异（有效 `4,058` 条、接纳 `28` 条，报告数值字段最大绝对变化为 `0`）。
- **内核改进：**滚动递推核按时间分块并行，块内严格保持原时间顺序累加，避免极值滑出窗口时产生灾难性相消残差；`ts_backfill` 改为并行向后查找，`ts_ref` 与 `ts_delta` 合并为单次内核启动。
- **回归验收：**PRO 6000 上 560 项测试（7,159 个子用例）通过，1 项旧协议私有基线按约定跳过；完整原始证据归档在本地 `var/runs/ops-opt-evidence.tar.gz`。
