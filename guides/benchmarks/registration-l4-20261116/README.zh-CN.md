## 改了什么

- 当前批次只创建一次连续 GPU 副本；评价直接使用这份副本，不从落盘数据重新上传。
- 持久化经页锁定主机缓冲区批量传输，暂存按 candidate_batch 分块。每块完成即释放，不建立全局页锁定缓存。
- 原生 SHA-256 直接读取连续内存视图；NPZ 直接流式写入原子临时文件，去掉完整 BytesIO 和额外字节副本。最多四个 Python IO 调度线程并行处理独立文件，保持返回顺序。
- GPU 缓存按整个底层分配淘汰，避免一个行视图拖住旧的大批次；混合命中/缺失的请求先组装完整批次再发布。

C++ 负责 CPU 性能敏感核，CUDA 负责批量并行计算，Python 负责接口、调度和生命周期。本次未增加 Python 数值循环：hashlib 原生实现执行哈希，Python 只调度 IO。

## 正确性与空间

- Smoke 后，79 项检查、6946 个子用例通过；包括四市场、PIT、RPC、强平与资金费、输入所有权、缓存淘汰、重载和写入失败清理。已有缺失价格除零警告记录在原始日志，不影响验收。
- 同卡旧/新各运行一次：269 日 × 500 美股，两类各 4×64 候选。完整报告、候选 SHA-256、奖励、学习更新、权重/硬准入、最终组合及因子邻域完全相同；最大绝对误差 0。
- MLP / 因子分别 47 / 74 个通过 G2；搜索相关性筛选后均入选 0 个。两类另各完成一次成功提交和过期报告 CAS 检查。因此循环计时包括提交检查，但不代表有成功入选时的重配开销。
- 当前批次最大约 32.84 MiB；候选容量 64、测量缓存 32 MiB。全 GPU 采样峰值从 924 / 1214 MiB 变为 962 / 1254 MiB，增加约 38 / 40 MiB，来自批量拥有与替换的暂态开销。空间仍为 O(candidate_batch × T × S)，不随已挖掘总数增长。
- 持久文件数量和体积不变：256 / 264 个，约 146 / 151 MB。可靠跨会话恢复仍需要一次主机传输与落盘，未宣称全程零拷贝。
- 因子注册占循环时间从约 67.0% 降至 50.6%。余下开销仍包含持久化传输、哈希和文件处理；本轮没有用性能分析器进一步拆分这三项，不能把余量全部归因于磁盘。
- 不更改算术、学习模型、探针或门槛。短数据窗口的延迟双生子仍为空，结果不构成稳健性或独立样本外收益证明。
- L4 已释放；生产组合基线未修改。测试只在 Colab 执行。
