# 历史记录：PRO 6000 内部接口基准

[当前公开接口基准](../../README.zh-CN.md) · [原始汇总](operator66-results.json) · [算子 CSV](operator66.csv) · [全部输入条件](operator66-cases.csv) · [公式语料](operator66-formulas.json)

这是一份旧版本记录：在同一台 Colab RTX PRO 6000 上，用 **500 只美股、269 个交易日、4096 条公式**比较 CPU 与 CUDA。它使用内部 Research 接口，不代表当前公开 API 的总调用耗时。

## 当时测到了什么

| 路径 | 评价 / 秒 | 按顺序接纳 / 秒 | 两项合计 / 秒 | 接纳数 |
| --- | ---: | ---: | ---: | ---: |
| CPU | 52.146807 | 44.908511 | 97.055318 | 28 |
| CUDA | 1.108764 | 1.478700 | 2.587464 | 28 |

在这次测量中，CUDA 的两项合计约快 **37.5 倍**。评价包含公式计算、持仓、回测指标和权重试探；接纳依次判断是否将候选加入组合。4058 条公式产生有效结果，38 条按缺失/非有限值规则拒绝。

**计时范围：**预热后的一次测量，使用内存组合；不含加载、准备/JIT、网络、磁盘保存和资源关闭。因此不能把 2.59 秒称为用户从打开会话到关闭会话的完整耗时。

## 输出是否一致

CPU/CUDA 的候选有效性、接纳身份、原因码、约束判断和持仓方向一致。最大绝对误差分别为：每日收益 `2.98e-14`、Sharpe `1.84e-7`、最大回撤 `2.18e-13`、选择权重 `8.14e-10`。这不是逐位一致的声明，也不代表其他市场或任意公式都得到相同结果。

## 精度实验为什么单列

旧实验还有一个“单 FP32 算术对照”：耗时 1.777887 秒，CUDA 正式路径为其 1.455 倍。但该对照仍共用双 FP32 统计和宽类型交换格式，并非全链单 FP32；它还出现了 227 项结构化/有限性差异。因此该数字只说明当时的算术成本，不能代表当前版本、其他 GPU 或不同批量已满足 1.5 倍预算。

## 旧算子表的限制

旧 CSV 覆盖 66 个算子、1550 个输入条件。CPU 使用墙钟时间，CUDA 主列使用设备事件时间，两列计时边界不同，不能直接当成调用加速比。各算子的条件数和窗口也不同，累计时间不能用来横向排名。

原始 CSV、公式和 JSON 保持原值，供追溯。当前套件已统一 CPU/CUDA 墙钟计时、固定窗口、公开 API、回归验证和报告生成；旧脚本不再作为维护中的入口。
