## 完整研究流程

同一 Colab RTX PRO 6000 Blackwell Server Edition，500 只美股 × 269 天，统计窗 249 个交易日。公开词表生成 4096 条去重公式，覆盖全部 66 个算子；每条都通过解析并进入算子计算。4058 条数值有效，38 条按缺失/非有限值规则拒绝，最终按输入顺序接纳 28 条。CPU 参考、单 FP32 对照、生产路径使用相同数据、公式顺序、空初始组合与市场规则。

| 路径 | 评价查询 / 秒 | 有序提交 / 秒 | 合计 / 秒 | 接纳数 |
| --- | ---: | ---: | ---: | ---: |
| CPU 参考 | 52.146807 | 44.908511 | 97.055318 | 28 |
| 单 FP32 对照 | 0.804018 | 0.973869 | 1.777887 | 28 |
| 生产 CUDA | 1.108764 | 1.478700 | 2.587464 | 28 |

生产路径约为本机 CPU 参考的 **37.51×** 速度；相对单 FP32 对照为 **1.455359×**，满足本次条件的 ≤1.5× 预算。每个条件预热后只计一次；这是一次测量，不是重复实验的均值或置信区间。

查询包含解析、全部公式算子、信号转持仓、账户回测、指标和权重试探；提交按输入顺序在工作组合上重做必要试探，完成版本检查和一次原子发布。使用进程内 Research 接口与内存组合存储，计时不含 RPC 网络及磁盘持久化。预热后清空报告缓存；提交正常复用用例允许的缓存。

生产 prepare 为 0.075613 秒、全公式预热为 1.065260 秒；对照分别为 0.365566、0.768251 秒，均不进入比例。prepare 依赖本轮已有 CuPy 编译缓存，不代表首次安装耗时。单 FP32 对照转换公式输入及公式/现金账户算术；两边共用双 FP32 统计和宽类型交换边界，因此不能称为全链单 FP32。

独立显存采样条件覆盖准备、预热、查询及提交，50 ms 采样设备总显存峰值 **5817 MiB**；它可能漏掉更短峰值。正式计时结束时生产运行时内存池保留 4492.7 MiB。显存采样那次流程不用于速度比例。

## 误差与决策

4096 条公式逐候选、逐阶段检查：有效性、准入/拒绝、结构化原因码、约束布尔值、接纳身份和持仓方向均一致。设备名称、组合版本哈希以及嵌入舍入数值的人类说明不要求字节相同。权重允许下表所列的微小数值差异。

| 比较量 | 最大绝对误差 |
| --- | ---: |
| 每日持仓权重 | 1.976832e-13 |
| 每日净收益 | 2.975398e-14 |
| Sharpe | 1.835835e-07 |
| CAGR | 4.810562e-13 |
| 最大回撤 | 2.183809e-13 |
| 选择权重 | 8.135211e-10 |
| 收益集中度 | 2.321225e-05 |

所有数值报告字段按 `abs(error)/max(1,abs(CPU))` 计算的最大尺度误差为 **7.409836e-07**，来自低净收益公式的收益集中度。它不是所有字段的绝对误差。单 FP32 对照有 227 项结构化/有限性差异记录，最大权重差 0.95，因此仅用于成本对照，未直接投入生产。

188 项全量测试在该 PRO 6000 上通过，覆盖 A 股规则、PIT、现货、永续资金费/强平、相邻强平阈值及准入阈值。收尾另修正 portable 两点协方差的无穷输入处理，并在第二个 PRO 6000 上通过 1 项新增专项；CUDA 与原生 CPU 数值核未变，计时不使用第二台实例。旧私有 `production/regression.npz` 缺少当前协议和研究身份，保留原文件并排除 `test_production`；没有重录，也不声称复现旧生产组合。这次完整 4096 公式计时只验证美股，不能外推为其他规模/市场已满足 1.5×；旧 64 公式及 4096 目标持仓结果也不能代替它。

## 算子优化及明确的数值修复

- 横截面排序与滚动中位数使用 IEEE 整数排序键，保留输入顺序，正负零同秩。中位数直接选择，省去大窗口张量排序。
- 回归、通道位置、回撤位置和区间缩放合并窗口扫描；偏度/峰度删除重复幂次计算与锚点数组；递推核调整调度粒度。
- 修复 `ts_av_diff` 的预热/缺失值均值语义，以及缩放/回归对小非零分母的错误拒绝。
- 两点窗口使用数学闭式结果；MAD、WMA 与横截面求和统一三个后端的顺序，消除零值附近的伪仓位。CPU 参考同步修复，旧基线未重录；这些不是通过放宽容差获得的一致性。

全部 66 项均已审计，并不声称每个轻量算子都变快。宽算术是本次完整流程预算内的固定策略，排序主要使用整数算术，现金账户/统计继续双 FP32；没有按结果切换精度复算，也没有声称这批算子使用 Tensor Core。
CPU WMA 由递推改为逐窗求和，复杂度变为 O(T×S×W)，这是保持确定舍入顺序的代价；不据此声称所有 CPU 工作负载提速。

## 复现

本次所有构建、CPU 参考、GPU 测试及计时只在授权 Colab PRO 6000 执行。本地只编辑、静态检查、打包和读取已保存结果。硬件/版本及源文件哈希在汇总 JSON 中。依赖与数据准备见仓库 README。

```bash
bash build.sh
python scripts/generate_precision_probes.py
PYTHONPATH=tests:. OMP_NUM_THREADS=2 python scripts/operator66_audit.py audit
PYTHONPATH=tests:. OMP_NUM_THREADS=2 python scripts/operator66_flow.py replay cpu_reference single production
PYTHONPATH=tests:. OMP_NUM_THREADS=2 python scripts/operator66_validate.py output/operator66/replay/formulas.json output/operator66/replay/validation.json
python scripts/operator66_compare.py replay replay
```

早期调试批次包含未开放的 `price` 字段，751 条在解析阶段被拒绝，其流程时间已作废；本文只引用从运行时公开词表重新生成、4096 条均实际执行的最终批次。候选语料 SHA 可由附带 JSON 核验，不通过挑选重复运行的较快结果满足预算。
