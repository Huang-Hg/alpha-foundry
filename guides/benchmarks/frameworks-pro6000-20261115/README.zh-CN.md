# Foundry 与 Spectre、vectorbt、Freqtrade 对比

[English](README.md) · [完整报告](report.zh-CN.md) · [逐项 CSV](summary.csv) · [方法与复现](../../framework-benchmark.zh-CN.md)

这轮受限日线现货测试中，**Foundry CPU 最快；CUDA 尚未超过自己的 CPU 后端**。64 个候选时，Foundry CUDA 端到端为 0.145 秒，vectorbt Numba 为 0.268 秒，Freqtrade 为 14.023 秒，Spectre 为 66.445 秒。但只有 1 个候选时，vectorbt 快于 Foundry CUDA。这是每条件一次测量的观察，不是四个项目的通用排名。

统一输入为 **8 个资产、549 根日线、365 个交易日**：BTC、ETH、SOL、BNB、XRP、ADA、DOGE、LTC。每个候选与资产拥有独立账户；因果 SMA 脉冲在次日开盘买入、再下一日开盘卖出，按前收盘价配置 25% 现金。最大批量为 **512 个账户、48,032 笔成交**。零费用与单边 10 bps 均在同一台 Colab RTX PRO 6000 Blackwell Server 上执行，CPU 请求两个线程。

## 误差与交易结果

- 36 个正式条件中，**入场决策与成交事件身份均零差异**；全部最终空仓，现金和账本核对通过。
- 零费最大归一化净值误差：Foundry CUDA **2.14e-13**，外部框架不超过 **4.89e-15**，参考为 Foundry CPU，预设门槛为 1e-8。
- 单边 10 bps 时，Foundry CUDA 最大净值/Sharpe 误差为 **1.57e-13 / 2.31e-12**；Spectre 为 **9.13e-8 / 1.87e-6**，保留了原生手续费按分取整。后者对应每 100 万初始现金不足 0.10 的净值差额；含费结果不宣称逐位相等。
- 含费的 512 个账户累计收益中位数为 **−7.26%**，范围 **−19.50%～+10.67%**。这是执行一致性用例，不是推荐策略。

Foundry 在这里的优势是紧凑的原生账户循环与批量数值路径。差距也很具体：小规模任务仍受 CUDA 启动和调度开销影响；现金内核提供收益结果，尚无独立原生成交账本。本报告明确将 Foundry 成交标为依据原生净值与单日持仓规则重建。Spectre、vectorbt 有原生账户历史；Freqtrade 提供原生订单和钱包，再依据实际成交计算收盘净值并核对。

三家对手运行的都是原生引擎。Spectre 批量计算因子，再通过原生因子缓存串行运行独立事件账户；Freqtrade 串行运行原生独立钱包，交易所部分仅注入离线元数据。其事件与订单功能有本用例不需要的开销。这里**不比较**共享钱包调度、止损订单、实盘执行、A 股限制、永续强平、Foundry 发现/准入，也不重新验收独立的 1.5 倍精度预算；不能推广为 GPU 普遍更快。
